01Resumen

El proyecto

Pro AI Assistant integra modelos de lenguaje en el flujo de trabajo de VS Code: un panel de chat con streaming, comandos sobre el código seleccionado (Explain, Fix, Optimize), generación de código a partir de una instrucción y mensajes de commit generados desde el diff de Git.

La interfaz está separada del modelo mediante un patrón adaptador, así que el mismo flujo funciona con Anthropic, OpenAI y Google Gemini, o con modelos locales en Ollama y LM Studio.

Problema

Muchos asistentes de código dependen de un solo proveedor o de un servicio en la nube, lo que limita el control sobre el costo, la privacidad y el modelo.

Objetivo

Construir un asistente extensible y con varios proveedores, organizado en capas: servicios, agentes y adaptadores de modelos.

Público

Desarrolladores que quieren IA en el editor y control sobre qué proveedor y modelo usar.

03Funcionalidades

Qué hace

Chat en streaming

Webview con respuesta fragmento a fragmento e historial persistente en un árbol propio.

Acciones sobre código

Explain, Fix y Optimize desde el menú contextual, como Quick Fixes o con Ctrl+Alt+E.

Generate

Genera código a partir de una instrucción en lenguaje natural, con el lenguaje y el contexto del archivo.

Mensajes de commit

Lee el diff staged o del working tree y escribe el mensaje en el campo de Source Control.

Varios proveedores

Anthropic, OpenAI, Gemini, Ollama y LM Studio, intercambiables desde la barra de estado.

Inline completion

Autocompletado experimental con debounce de 400 ms.

04Arquitectura

Cómo está construido

activate()
  └─ AppContext ─┬─ SettingsService   (config + SecretStorage)
                 ├─ AIService ──► createModelProvider()
                 │                 ├─ AnthropicProvider  (messages.stream)
                 │                 ├─ OpenAIProvider · GoogleProvider
                 │                 └─ OllamaProvider · LMStudioProvider
                 ├─ PromptService     (src/prompts/*.md)
                 ├─ History · Context · Workspace
                 └─ agents: chat · coding · refactor · review · docs
providers: Webview · TreeView · CodeActions · InlineCompletion · StatusBar
  • Inyección de dependencias manual: un único AppContext compartido por comandos y providers.
  • Cada proveedor implementa chatStream() como un AsyncGenerator, así que agregar uno no afecta a la UI.
  • Los prompts son plantillas Markdown versionadas, separadas del código.

06Ingeniería

Decisiones y próximos pasos

Seguridad

  • Las API keys se guardan en SecretStorage, nunca en settings.json.
  • El webview usa una Content-Security-Policy estricta (default-src 'none', scripts con nonce).
  • Con Ollama o LM Studio se puede trabajar 100 % en local.

Retos técnicos

  • Unificar APIs de streaming distintas en una sola interfaz.
  • Coordinar el streaming entre la extensión y el webview por mensajes.
  • Controlar la frecuencia de las peticiones del autocompletado inline.

Hoja de ruta

  • Conectar los agentes review y docs a comandos.
  • Hacer opcional el autocompletado inline por lenguaje.
  • Ampliar las pruebas y publicar en el Marketplace.
